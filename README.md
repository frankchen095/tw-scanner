# 台股盤後掃描推播

每天收盤後自動抓 FinMind 與公開資料,算出各策略的篩選結果,做成 PDF 報表(放在 GitHub Pages),
**用 LINE 推播「摘要 + PDF 連結」**;PDF 或發佈失敗時退回文字訊息(每段標 §編號)。
GitHub Actions 排程(台灣時間週一~週五 21:00;GitHub 的排程常比設定時間晚幾小時才啟動,
另外有一個 Windows 排程工作 `tw-scanner-daily` 在 21:00 手動觸發,要電腦開著才會跑;
手動觸發時勾選 dry_run 可以只跑完整流程、不推播)。

> 這是程式依公開資料自動整理的篩選結果,不是投資建議;歷史命中率不代表未來表現。

## 目前推播的內容

**推播順序**(文字版每段標 §編號,方便在手機上找;PDF 版依這個順序分頁):

1. §1 交集榜 → 族群訊號(K)
2. 價格位置:策略一、策略五
3. 策略二(買超榜、賣超榜、近3日買超榜)
4. 法人:策略八、策略九

6. 大戶持股比(策略十四,F,**只在集保新一週資料入庫的那一天**)
7. 空方區:策略三(漲停放空)、策略十三(借券賣出餘額,D)、散戶接刀榜(E)
8. 事件區:策略四(月營收公布)、策略十五(財報毛利率轉折,G)、基本面動能榜(G 擴充,**只在特定日子**)、負面新聞掃描(H)
9. 策略七(地緣/庫藏股分點)→ 策略十(美日族群創新高)→ 行事曆
10. 策略六(時事分析:供需訊號 / 總經大事 / 財報展望解讀)→ 成效追蹤(**只在每週五**)

**共同規則**:股票池 = 上市 + 上櫃普通股(排除興櫃、ETF、ETN、權證、存託憑證、特別股);
有寫市值條件的策略一律 **市值 > 500 億**,市值用 FinMind `TaiwanStockMarketValue`(= 收盤價 × 已發行股數);
跟股價高低點有關的計算一律用還原股價 `TaiwanStockPriceAdj`;抓不到資料就標「今日無資料」,不編造、不估算;
任何新的外部資料來源,先實際請求一次、確認欄位和更新頻率才寫進程式。

### 已知限制(請看這裡)

- **策略四「當天公布」是以 FinMind 入庫日判斷**:FinMind 的 `create_time` 是入庫日,不是公司的精確
  公布時間,可能比實際公布晚(例如台積電 2026 年 6 月營收的入庫日是 7/13 週一)。所以某公司可能在
  公布後的隔天才出現;晚上才公布的,也會在隔天出現,不會漏掉。
- **季報「今天新公布」(策略十五、動能榜)是自己記的**:FinMind 季報沒有入庫日欄位,所以每天重查最近季度的全市場資料,
  資料庫裡還沒有的(股票, 季度)就算「今天新入庫」。季底超過 100 天的季度視為歷史、不算新公布。
  可能比公司實際公布晚一兩天;金融股等沒有毛利欄位的算不出毛利率,直接略過並在報表註明略過幾檔。
  FinMind 損益表是單季值(實測台積電 2026 Q2 營收 1.27 兆)。
- **集保股權分散(策略十四)**:FinMind `TaiwanStockHoldingSharesPer`,全市場一次查某一天,沒資料的日期回傳空;
  大戶 = 級距『1,000,001 股以上』(≥1,000 張),散戶 = 前 11 級(1~400,000 股,≤400 張)的持股比合計。
  第一次執行補 35 天歷史(標 baseline,不算今天新入庫);只在新一週資料入庫的那一天推播。
- **法說會**:公開資訊觀測站沒有 JSON/CSV,只能解析網頁表格,而且連續請求會被斷線;在 GitHub Actions
  的雲端 IP 可能被擋。抓不到時,報表最後會明確寫「法說會標記可能不完整」,不會假裝沒事。
- **內部人轉讓申報(策略十六)**:OpenAPI 每天只提供最近一個營業日那一份(出表日期),所以我們每天存起來;
  報表只列「出表日期 = 報表日」的申報;事前申報不等於一定會賣,申報股數是上限,申報後 3 日起 1 個月內可以賣。
- **「漲停股被限制平盤下放空」找不到對應的公開資料**(證交所那欄只對「前一天跌停」的股票有意義),
  策略三只標「能不能融券」(暫停融券賣出、停券預告、沒有融資融券資格),不拿處置股當替代。
- 策略一、五用『收盤價』比高點(不是盤中最高價);新上市不足60個交易日的股票無法判斷,會在報表最後列出略過幾檔。
- 融券狀態以報表當天的名單為準(證交所隔天的名單要到晚上8:30以後才公布)。
- **負面新聞掃描**:標題含公司名不代表那家公司是當事人(例如「XX 控告 YY」兩家都會被抓到;短名稱也可能誤中,
  例如「幸福人壽」會比對到「幸福」),這段只是提醒,要自己看。
- **連續天數(交集榜「連 N 日」、策略二「連 N 日上榜」、族群「連 N 日」)只算正式推播的紀錄**:dry-run 不記訊號,
  所以只能從 `signals` / `group_signals` 表算;中間哪天沒推播,連續天數就在那天斷掉。
- **策略七 A(同區分點)的地址**:公司地址只寫「新竹科學園區」沒寫區的(台積電、聯發科、聯電、瑞昱…約 30 家,
  清單在 `data/geo_unparsed.txt`)沒辦法判斷是哪個區,所以不參與比對,我不猜。你確認後,把縣市+區填進
  `data/geo_overrides.json`(格式見 `scripts/geo.py` 最上面),下次每月更新對照表就會生效。
  地址有做的固定處理:台/臺統一、異體字「巿」改「市」、去掉開頭的郵遞區號和「新竹科學園區」、
  「北市…」視為臺北市、14 個縣轄市(彰化市、竹北市…)補上縣名。
- **策略七 B(庫藏股分點)是推算出來的**:公告不會寫用哪個分點,用 fenpoint 的分點歷史資料(400 檔、
  2023-01 起)推算,兩層規則,第一層沒辨識出來的才用第二層:
  (1)『股數對上』:買回期間內累計淨買超股數與公告已買回股數誤差 ≤ 5%,而且『持續買超』(這個分點有
  淨買超的交易日占它有交易的天數 ≥ 70%),剛好只有 1 個分點符合。不設賣出上限;持續買超是用來
  擋『一般營業處買買賣賣、淨買超數字剛好碰巧接近』的巧合。
  (2)『穩定買超』:看公布實施庫藏股後哪個分點穩定在買——有淨買超的天數 ≥ 70%、交易天數 ≥ 買回期間的
  一半、淨買超最多,而且 ≥ 第二名的 2 倍(或只有它一個),淨買超落在公告股數的 70%~130%。
  結果:592 筆計畫(369 家公司)中,辨識成功 71 筆、53 家公司(第一層 43 筆/35 家,第二層 28 筆/24 家),
  其中市值>500億的 20 家;策略七 B 不限市值,53 家都會追蹤。第一層的 43 筆裡仍有 7 筆賣出占比超過 10%,
  可能是巧合。`data/buyback_match_report.csv` 可以看到每一筆用哪一層、賣出占比、買超天數占比。
  公告的『實際已買回股數』要等計畫執行完畢才會填,所以執行中的計畫還不能用來推算,只能標「庫藏股執行中」。
- **FinMind 的「市值表」比其他資料晚更新**(2026-10-07 實測:股價、法人、分點日報 21:00 都有,市值表 21:25 還沒有)。
  所以『市值>500億』的門檻,當天的市值表還沒更新時**用前一個交易日的市值表**(你決定的,這樣比較快),
  報表最後會註明用的是哪一天的;當天的有了就用當天的。
- **策略十(美日族群創新高)**:用 Yahoo Finance 公開行情的『還原收盤價』;沒抓到的 ETF 會列在最後,不用別的資料頂替。
  『前一天』:晚上 21:00 美股當天還沒開盤,所以美國取報表日以前最新一個已收盤交易日;日本當天 14:00(台灣時間)就收盤了,取當天。
- **行事曆**:美股財報來自 Nasdaq 公開財報日曆(日期是美東日期);經濟數據來自 Nasdaq 經濟日曆,只留美國的主要項目;
  Nasdaq 的時間欄位跟日期對不上,所以只列日期不列時間;FOMC 日期來自聯準會官網。
- **策略六的新聞來源**(`scripts/news_sources.py`,只抓標題和摘要,不抓全文、不繞付費牆、不用 cookie 登入):
  Google News RSS(上限 60 則)、金十數據快訊(40 則)、華爾街日報公開 RSS(20 則)、富途牛牛快訊(20 則)。
  金十用的是它網頁版快訊頁自己的請求(需要網頁自己帶的公開 header;**不是官方開放 API**,沒有保證,隨時可能改);
  金十一天幾百則,用關鍵字過濾只留跟台股有關的;富途大多轉載金十,跟金十標題去重後只剩約 3 則個股/獨家;
  WSJ 英文標題直接給 Claude。候選存在 `news_candidates` 表,連續兩天同標題不重複送給 Claude。
  任一來源抓不到只會在策略六最後註明「本日 XX 來源問題」,不會讓整段掛掉。
- **成效追蹤的算法**(也寫在每週五的彙總裡):進場價 = 訊號隔天(下一個交易日)的開盤價,用還原股價;
  5日/20日 = 進場日算第 1 天的第 5/第 20 個交易日收盤;報酬 = 出場 ÷ 進場 − 1;勝率 = 報酬>0 的比例;
  標〔偏空〕的是放空訊號,報酬和大盤對照都反向計算(大盤跌才算贏);大盤對照 = 加權指數(FinMind `TaiwanStockPrice` 的
  `TAIEX`)同一段,進場日開盤進、同一個出場日收盤出;交易日用加權指數的交易日當日曆(國定假日不會算錯)。
  同一檔股票連續幾天出現,每一天各算一筆訊號,所以樣本不是互相獨立的。
  只有「正式推播」才會記錄訊號(dry-run 不記,免得測試資料混進去);報酬每天更新一次。
  週五剛好是國定假日(例如 2026-10-09)那週就沒有週五推播。
- **LINE 訊息量**:PDF 連結成功時每天只有 1 則;退回文字版時全部策略展開約 5~8 則,
  免費方案一個月約 200 則推播額度(見 `scripts/04_line_test.py` 查實際額度),文字版連續多天會吃額度。
- 舊的「功能1(大摩+法人排行)、功能2(外資投信同買)、功能4(帶量突破盤整)」已停用,程式檔案還在
  `scripts/reports/`,但沒有被呼叫。

## 歷史回測(L 項)

`scripts/backtest.py`:**直接重用每個策略的 `build()`**,一天一天重播,不另寫簡化版邏輯;訊號存進獨立的
`backtest_signals`(跟正式的 `signals` 分開),報酬算法跟成效追蹤一樣;資料放在 `data/backtest.db`(很大,不進 repo)。
輸出 `data/backtest_<起>_<迄>.csv`(每筆訊號一列)和 `data/backtest_summary.md`(每個策略一列:訊號數、5日/20日平均報酬與勝率、
同期大盤、超額報酬、按年份拆開、隨機抽樣基準、一句話結論)。

- **能測**:策略一、三、四、五、八、九、交集榜(交集榜的「質押」類別沒有歷史);策略二、三、七需要分點日報,只有 fenpoint 的 400 檔、到 `chips.db` 最後一天(2026-09-15)為止。
- **不能測**(不假裝測):策略六(AI 時事)、負面新聞(RSS 只有近期)、質押/內部人轉讓(沒有歷史)、風險標記裡的法說會。
- **偏誤處理**:策略二的前40大分點名單是用 2023–2024 資料篩出來的,所以**分開報 2024(樣本內)和 2025 至今(樣本外),只有樣本外算數**;
  股票池用現在的股票名單(已下市的不在,存活者偏誤);市值門檻用當天市值;交易日用 TAIEX;交集榜另算「只算首次出現」、「連 2 日以上」、「單日」三版。
- **隨機抽樣基準**:每天從當天市值>500億的股票隨機抽跟訊號數一樣多的檔數,重複 100 次取平均;策略贏不了它就是沒有訊號。
- 樣本數 N<30 標「樣本不足」。
- 回補**要加 `--yes`** 才會真的花 FinMind 額度;先跑 `--plan` 看缺口與請求次數估算。

### 回測結果摘要(2024-01-02 ~ 2026-10-16,完整表格在 `data/backtest_summary.md`)

- **策略二(只看樣本外 2025 至今)**:20 日平均 +6.0%、勝率 59%、超額 +2.4%(同期隨機抽樣基準 +3.3%),5 日超額約 +0.3~0.4%——**唯一明顯贏過隨機抽樣的**。2024 年(樣本內)反而輸給大盤,所以前 40 大分點名單有一部分是用答案考試,以 2025 起為準。
- **策略八(法人買超)20 日**:超額約 +0.9~1.0%、勝率 56~57%,有效但幅度小;5 日無效。
- **策略九(投信)20 日**:超額只有 +0.06%,勉強,不算有說服力;策略九(外資)無效。
- **策略一、四、五、七、交集榜**:20 日超額接近 0 或為負,輸給或打平隨機抽樣(交集榜 20 日超額 +0.35%,只算首次出現那天 +0.56%、連 2 日以上 +0.22%——持續天數沒有帶來更好的成績)。
- **策略三(漲停放空)**:放空 20 日平均 −9.6%、勝率 38%,明顯無效(漲停後多半還繼續漲)。
- 注意:2024~2026 是多頭,大盤同期 20 日平均 +3%,所以「平均報酬為正」不代表策略有用,要看超額和隨機基準。策略二、三、七只測到 2026-09-15(分點資料到那天為止)。
